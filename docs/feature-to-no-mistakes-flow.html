Single feature workflow

From Feature Idea to PR

Use this one path for new feature work: create the Treehouse worktree, clarify with Grill Me, choose the lightest planning artifact, implement, prove, review, then finish with no-mistakes.

1. WorkspaceTreehouse first. Work from that isolated worktree.
2. ClarityGrill Me resolves what is being built and why.
3. BuildUse only the planning and specialist skills the feature needs.
4. ShipNo-mistakes is the final gate and PR path.

  1. Create the Treehouse worktree

    Every new feature starts in Treehouse. Planning, implementation, verification, commit, and PR handoff stay in that worktree.

    $ treehouse <feature-name>

  2. Use Grill Me

    Clarify the user, outcome, acceptance criteria, proof path, and out-of-scope work before planning or coding.

    /grill-me

  3. Choose the planning artifact

    This is a decision, not a required sequence. Pick the lightest option that makes the work clear enough to build.

    Pick one path

    Small and clearSkip this step.
    Need a briefUse /to-prd.
    Need slicesUse /to-issues.
    Big featureUse /to-prd, then /to-issues.

  4. Implement in the canonical owner

    Change the real owner. Avoid wrappers, temporary modes, hidden fallback paths, and weak validation.

    /codebase-design
    UIatomic-ui and impeccable.
    React or Nextreact-doctor, fallow, and Vercel best practices.
    Risksecurity-review or performance-rescue only when relevant.
    PlatformUse Flutter, Appwrite, Sentry, PDF, video, or research skills only when touched.

  5. Prove it works

    Run behavior tests for code changes. If the user sees or clicks the flow, run E2E and keep the evidence.

    /test-quality
/e2e

  6. Review before shipping

    Run the strict maintainability review for meaningful changes. Add specialist reviews only for real risks.

    /thermo-nuclear-code-quality-review

  7. Finish with no-mistakes

    After implementation, proof, review, status, secrets, and commit are complete, run no-mistakes. It owns the final check and PR generation.

    /no-mistakes

Before no-mistakes

  • Treehouse worktree exists.
  • Grill Me resolved the feature outcome and proof path.
  • Planning artifact decision is explicit: skipped, PRD, issues, or both.
  • Canonical owner and blast radius were checked.
  • Tests and E2E evidence match the changed behavior.
  • Review blockers are fixed.
  • Worktree changes are committed with no secrets or unrelated files.
