Single feature workflow

Plan, Implement, Verify

Use three stages for feature work. Plan enough to know the owner and proof path, implement in the canonical owner, then loop between fixes and verification until local blockers are gone. No-mistakes is the final gate.

1. PlanTreehouse and Grill Me gate non-trivial feature work.
2. ImplementChange the real owner with only needed specialist skills.
3. Verify LoopTest, review, fix, then run E2E last when needed.
4. Final GateNo-mistakes runs after the local loop is clean and committed.

  1. Plan the work

    For non-trivial feature work, start in Treehouse and use Grill Me when outcome, scope, proof, or risk is unclear. Pick the lightest planning artifact that makes the work buildable.

    $ treehouse <feature-name>
/grill-me

    Pick one planning path

    Small and clearSkip this step.
    Need a briefUse /to-prd.
    Need slicesUse /to-issues.
    Big featureUse /to-prd, then /to-issues.

  2. Implement with touched-area skills

    Change the real owner first. Load only the specialist skills required by the files, stack, or risk you touched. Avoid wrappers, temporary modes, hidden fallback paths, and weak validation.

    /codebase-design
    Owner unclearUse codebase-design.
    UI touchedUse atomic-ui and impeccable.
    React or Next touchedUse react-doctor, fallow, and Vercel best practices.
    Platform touchedUse Flutter, Appwrite, Sentry, PDF, video, or research skills.

  3. Verify in a loop

    Run tests, requested or touched risk reviews, thermo review, then E2E. Any blocker goes back to implementation; repeat until clean.

    /test-quality
/security-review
/performance-rescue
/thermo-nuclear-code-quality-review
/e2e
    3a. Targeted testsUse test-quality for design, gaps, or repairs.
    3b. Risk reviewsSecurity/perf if requested or touched.
    3c. Thermo reviewMaintainability before E2E.
    3d. E2ERun last for user-visible flows and artifacts.
    If any fail: back to 2. Implement, then rerun Verify.
    Pass: go to 4. Final Gate.

  4. Finish with no-mistakes

    After the local verify loop is clean, status and secrets are checked, and the work is committed, run no-mistakes. It owns the final check, PR generation, and its own findings loop.

    /no-mistakes

Before no-mistakes

  • Treehouse and Grill Me gate was used or explicitly skipped for small clear work.
  • Planning artifact decision is explicit: skipped, PRD, issues, or both.
  • Canonical owner and blast radius were checked.
  • Tests, review, and required E2E are clean after the latest fix.
  • E2E evidence exists for changed user-visible flows.
  • Worktree changes are committed with no secrets or unrelated files.
